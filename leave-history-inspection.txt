2. EXACT SERVICE METHOD

File: src/leave/leave.service.ts

async leaveHistory(role: string, employeeId: number) {
  return this.prisma.leave.findMany({
    where: {
      ...(role === 'EMPLOYEE' && { employeeId }),
    },
    include: {
      employee: {
        select: {
          id: true,
          firstName: true,
          lastName: true,
          empCode: true,
          user: { select: { email: true } },
        },
      },
      leaveType: true,
    },
    orderBy: { createdAt: 'desc' },
  });
}

5. MANAGER/HR/ADMIN SCOPE

Yes. For MANAGER, HR, and ADMIN, the query has no employeeId filter and returns leave records for all employees.

Only EMPLOYEE requests are filtered by employeeId.

There is no team-based filtering for managers.

6. DATE AND STATUS FILTERING

The query does not filter by date.

The query does not filter by status.

It can return records with these statuses:

- PENDING
- APPROVED
- REJECTED
- CANCELLED

7. ORDERING

Records are ordered by createdAt descending:

orderBy: { createdAt: 'desc' }

The newest leave applications are returned first.

8. PAGINATION SUPPORT

Pagination is not supported by this method.

The method does not accept or use:

- page
- limit
- skip
- take
- cursor
