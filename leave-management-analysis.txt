LEAVE MANAGEMENT ANALYSIS

1. LEAVE-RELATED PRISMA MODELS

File: prisma/schema.prisma

- LeaveType: Defines leave categories, yearly quota, monthly accrual, medical requirements, and carry-forward rules.
- LeaveBalance: Stores each employee's allocated, used, and carried-forward leave balance for a financial year.
- Leave: Stores leave applications, dates, duration, reason, status, remarks, and medical certificate.
- Employee: Has relations to leaves and leave balances.

Leave statuses:
- PENDING
- APPROVED
- REJECTED
- CANCELLED

Leave duration types:
- FULL_DAY
- HALF_DAY_FIRST
- HALF_DAY_SECOND

3. LEAVE API ENDPOINTS

All endpoints require JWT authentication.

POST /api/leaves/apply
Employee submits a leave application.

PATCH /api/leaves/approve/:id
Manager, HR, or admin approves a leave request.

PATCH /api/leaves/reject/:id
Manager, HR, or admin rejects a leave request. Rejection remarks are provided in the request body.

GET /api/leaves/history
Employees receive their own leave history. HR, managers, and admins receive all leave history.

GET /api/leaves/pending
Returns all pending leave requests. Employees are denied access.

GET /api/leaves/all
Returns all leave requests. Employees are denied access.

GET /api/leaves/balance?yearStart=YYYY
Returns leave balances.

GET /api/leaves/self/history
Returns the logged-in employee's leave history.

GET /api/leaves/self/balance?yearStart=YYYY
Returns the logged-in employee's balance.

POST /api/leaves/carry-forward
Requests leave carry-forward.

4. HOW AN EMPLOYEE APPLIES FOR LEAVE

The request is handled by:

- src/leave/leave.controller.ts
- src/leave/leave.service.ts

The employee ID is taken from req.user.employeeId.

The service:

- Validates the employee.
- Validates the leave type.
- Validates the date range.
- Calculates the number of leave days.
- Determines the financial year.
- Prevents overlapping non-rejected leave requests.
- Creates a leave balance if one does not exist.
- Checks available leave balance.
- Requires a medical certificate when configured and the leave exceeds two days.
- Creates the leave record with status PENDING.

5. MANAGER APPROVAL AND REJECTION

Approval and rejection are implemented in:

src/leave/leave.service.ts

Allowed roles:

- MANAGER
- HR
- ADMIN

Approval:

- Only pending requests can be approved.
- The leave status changes to APPROVED.
- LeaveBalance.used increases by the leave duration.
- The leave update and balance update occur in one database transaction.

Rejection:

- The leave status changes to REJECTED.
- Remarks are stored.
- The employee's used balance is not changed.

There is no check that a manager belongs to or manages the applicant's team. Any user with the MANAGER role can approve or reject any leave request.

6. HOW HR VIEWS AND PROCESSES LEAVE

HR can use:

- /api/leaves/pending to view pending requests.
- /api/leaves/all to view all requests.
- /api/leaves/history to view leave history.
- /api/leaves/balance to view balances.
- /api/leaves/approve/:id to approve requests.
- /api/leaves/reject/:id to reject requests.

There is no separate HR controller. HR functionality is handled by the common leave controller and service.

7. WHERE LEAVE STATUS IS STORED AND UPDATED

Status is stored in:

prisma/schema.prisma

Model field:

Leave.status

Status values are defined by the LeaveStatus enum.

Status is set to PENDING when the leave is created.

It is updated to APPROVED during approval and to REJECTED during rejection.

No current API updates a leave to CANCELLED.

8. HISTORICAL LEAVE RECORDS

Yes, historical records are already returned.

The following APIs return previous records:

- /api/leaves/history
- /api/leaves/self/history
- /api/leaves/all

These queries do not filter by year or status. Therefore, they can return pending, approved, and rejected records.

Records are ordered by createdAt descending, newest first.

9. PAGINATION

Pagination does not currently exist for leave records.

The leave APIs do not accept page, limit, offset, or cursor parameters. The Prisma queries do not use skip, take, or cursor pagination.
