A. AUTHORITATIVE ATTENDANCE SERVICE / RESULT
============================================================
Source of truth:
- src/attendance/attendance.service.ts

Key observations:
- Attendance status is derived in the attendance service using effectiveStatus(), effectiveRecord(), buildLeaveAwareStatusMap(), and getAttendanceHistory().
- The service decides present / absent / half-day / leave / in-progress using stored clock-in and clock-out records and applied leave-overlap rules.

C. AUTHORITATIVE LEAVE SERVICE / RESULT
============================================================
Source of truth:
- src/leave/leave.service.ts

Key observations:
- applyLeave() validates date range, overlap, working-day inclusion, policy/annual quota, and medical-document rules.
- It creates a Leave record containing totalDays, durationType, isLossOfPay, yearStart, and related metadata.
- approveLeave() checks the relevant LeaveBalance and increments used by leave.totalDays when approved and not LOP.
- leave overlap validation, eligibility, quota assignment, and approval flow all live here.

Current limitation:
- The system can represent only a single boolean isLossOfPay on a leave request.
- It cannot express one request containing both paid days and LOP days.
- This is exactly why the leave quota + LOP requirement is sensitive.

============================================================
D. AUTHORITATIVE LEAVEBALANCE FLOW
============================================================
Source of truth:
- src/leave/leave.service.ts
- prisma/schema.prisma

Key observations:
- LeaveBalance has: employeeId, leaveTypeId, yearStart, allocated, used, carryForward.
- getBalance() and selfBalance() compute remaining as:
  allocated + carryForward - used
- approveLeave() increments used by totalDays only for non-LOP approved leave.
- cancelLeave() decrements used only for approved non-LOP leave.

This means:
- LeaveBalance.used is currently treated as the paid-consumed total.
- LOP does not currently reduce used.
- The design requirement is aligned with this intended semantics, but the current Leave model cannot represent mixed paid + LOP split within one request.

============================================================
E. AUTHORITATIVE PAYROLL CALCULATION FLOW
============================================================
Source of truth:
- src/payroll/payroll.service.ts
- src/payroll/payroll.scheduler.ts

Key observations:
- computePayroll() calculates workingDays for the month.
- It fetches attendance history through AttendanceService.
- It counts present and leave days to derive payableDays.
- It computes:
  payableDays = presentDays + approvedLeaveDays
  lopDays = max(workingDays - payableDays, 0)
- Payroll then runs PayrollCalculator.calculate() with workingDays and lopDays.

Important issue:
- Payroll currently reconstructs leave-day business logic from attendance + leave records instead of consuming a canonical leave-domain split.
- This violates the requirement that payroll must consume the authoritative Leave result and not independently reconstruct leave/LOP rules.

============================================================
Attendance display-only location classification:
- backend canonical location classification should be derived from existing attendance geolocation and office location logic
- do not change underlying attendance status rules
- classify based on check-in and check-out relative to office boundary

Requested display mapping:

============================================================
PHASE 4: REQUIREMENT 3 DESIGN
============================================================
The most sensitive requirement is leave quota + LOP behavior.
Current state:
- LeaveService is the authoritative source for leave decisions
- LeaveBalance used should represent only paid leave consumed
- LOP must not reduce paid balance

Required canonical split:
- requestedDays
- paidLeaveDays
- lopDays

Minimal additive schema change:
- add paidLeaveDays and lopDays to the Leave model
- keep existing totalDays and isLossOfPay for compatibility
- ensure LeaveBalance.used increments only by paidLeaveDays

Formula:
- paidLeaveDays = min(requestedDays, available paid quota)
- lopDays = max(requestedDays - paidLeaveDays, 0)
- this works for multi-day and half-day requests

Approved behavior:
- PENDING: no paid balance consumption
- REJECTED: no paid balance consumption
- CANCELLED: restore only the paid portion already consumed
- APPROVED: consume only paidLeaveDays; persist canonical LOP portion

Payroll must consume the authoritative Leave result and not recalculate its own leave/LOP rules.

Maternity logic must remain centralized in Leave domain and must not be implemented as a hardcoded employee gender check.
