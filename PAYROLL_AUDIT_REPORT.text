B. CURRENT END-TO-END PAYROLL FLOW

1. The frontend opens Payroll.
2. It calls GET /payroll/my for the logged-in employee's payroll history.
3. It calls GET /employees/me for salary details.
4. Org-wide users can open Run Payroll and Assign Salary.
5. Run Payroll sends POST /payroll/run.
6. The backend resolves employeeId or empCode and validates month/year.
7. It selects the latest EmployeeSalary effective before the payroll month end.
8. It calculates working days through WorkingDaysService.
9. It loads attendance records.
10. It loads overlapping approved leave records.
11. It calculates present days, payable days, LOP days, earnings, deductions, and net salary.
12. It creates Payroll with default status DRAFT.
13. Payroll history is displayed in the frontend.
14. Payslip download calls GET /payroll/payslip/:id.
15. Adjustments call POST /payroll/others.

The scheduler separately generates payroll for active employees on the 29th of each month.

C. EXISTING BUSINESS RULES AND CALCULATIONS

Salary selection:
- EmployeeSalary must match the employee.
- effectiveFrom must be on or before the payroll month end.
- The latest effective salary is selected.
- Salary assignment stores monthlyCTC as annualCTC / 12.
- Salary assignment currently rejects a second salary row for the employee, despite frontend raise-mode text.

Earnings:
- basic = monthlyCTC * basicPercent / 100
- hra = basic * hraPercent / 100
- conveyance = monthlyCTC * conveyancePercent / 100
- specialAllowance = monthlyCTC - basic - hra - conveyance
- gross = basic + hra + conveyance + specialAllowance

Deductions:
- pf = basic * pfPercent / 100
- pt = structure.ptAmount || 0
- perDaySalary = gross / workingDays
- leaveDeduction = lopDays * perDaySalary
- deductions = pf + pt + leaveDeduction
- netSalary = gross - deductions

All calculator values are rounded with Math.round().

Attendance:
- PRESENT contributes 1 day.
- LATE contributes 1 day.
- HALF_DAY contributes 0.5 day.
- Other statuses contribute 0.

Leave:
- Only APPROVED leaves are included.
- Overlapping leaves are prorated across month boundaries.
- approvedLeaveDays += leave.totalDays * overlapDays / leaveSpanDays.
- payableDays = presentDays + approvedLeaveDays.
- lopDays = max(workingDays - payableDays, 0).
- Leave days are not filtered against weekends, holidays, or attendance.

Adjustments:
- ALLOWANCE increases grossSalary and netSalary.
- DEDUCTION increases deductions and decreases netSalary.
- Adjustments are created and Payroll totals are updated in separate operations.
- Payroll.otherAllowance exists but is not updated by addOther().

Working days:
- Sunday is always excluded.
- Saturday is excluded for normal teams.
- Saturday is included when the employee team name is SALES.
- Holidays are excluded through HolidaysService.isHoliday().
- isHoliday checks date only; employee location is not applied.

Period inconsistency:
- Manual payroll uses the first through last calendar day of the month.
- Scheduler payroll uses the 29th of the previous month through the 28th of the current month.

D. ROLE AND AUTHORIZATION MATRIX

Role              View own  View others  Generate  Assign salary  Adjust  Payslip others
SUPER_ADMIN       Yes       Yes          Yes       Yes             Yes     Yes
CEO               Yes       Yes          Yes       Yes             Yes     Yes
HR                Yes       Yes          Yes       Yes             Yes     Yes
FINANCE_MANAGER   Yes       Yes          Yes       Yes             Yes     Yes
IT_MANAGER        Backend team scope; frontend route blocked       Team-scoped
SALES_MANAGER     Backend team scope; frontend route blocked       Team-scoped
EMPLOYEE          Own only  No           No        No              No      Own only

Backend org-wide access is granted to SUPER_ADMIN, CEO, HR, and FINANCE_MANAGER.
IT_MANAGER and SALES_MANAGER access is based on teams managed by the authenticated employee.
EMPLOYEE access is restricted to the authenticated employee ID.

The backend uses authenticated JWT role and employeeId for authorization. Client-supplied employeeId is accepted for org-wide operations, which are controller-role restricted.

E. FRONTEND FINDINGS

Working:
- Payroll route exists.
- Self-service payroll uses /payroll/my.
- Salary details use /employees/me.
- Payslip download exists.
- Run Payroll, Assign Salary, and Add Adjustment modals exist.
- Loading, error, and empty states exist.

Issues:
- Sidebar shows Payroll to every authenticated user, including roles blocked by the route.
- Route allows SUPER_ADMIN, CEO, HR, FINANCE_MANAGER, and EMPLOYEE, but not IT_MANAGER or SALES_MANAGER.
- Adjustment controls appear to employees even though backend rejects employee adjustment requests.
- Adjustment controls remain visible for FINALIZED and PAID payrolls until submission is rejected.
- Frontend locally calculates salary values using a default structure that may differ from backend structure values.
- Frontend displays conveyance, but Payroll does not persist a conveyance column.
- Frontend uses substantial any typing.
- Run Payroll filters employees with no payroll history, while backend only checks whether the requested employee/month/year already exists.
- Frontend describes scheduler behavior but does not model payroll lifecycle.
- /payroll/my and /payroll API helpers convert many errors into empty arrays.

G. DATABASE AND SCHEMA FINDINGS

Payroll-related models:
- SalaryStructure
- EmployeeSalary
- Payroll
- PayrollAdjustment
- Employee
- User

Current constraints:
- Payroll has foreign keys to Employee and EmployeeSalary.
- EmployeeSalary references Employee and SalaryStructure.
- PayrollAdjustment references Payroll.
- Payroll has a unique employeeId/month/year constraint.
- EmployeeSalary has an employeeId index.

Limitations:
- Payroll has no updatedAt.
- No approval, finalization, or payment fields.
- PayrollStatus only has DRAFT, FINALIZED, and PAID.
- No status transition history.
- No payroll period or batch model.
- No payment reference/date.
- No persisted conveyance field.
- healthInsurance and pfBase are present in SalaryStructure but unused by calculation.
- otherAllowance is present but not maintained by adjustment logic.
- No adjustment audit metadata.
- No protection against overlapping salary effective periods.
- No constraint against duplicate salary effective dates.

Payroll was introduced in migration 20260305084833_payroll and subsequently evolved through Payroll and SalaryStructure migrations, including removal of legacy fields and schema drift resolution.

Leave:
- Approved leave is included but may count weekends and holidays.

Teams:

AuthorizationService:
- Reused for employee salary, payslip, employee 360, and manager scope checks.
- Core Payroll generation/list operations rely mainly on controller role decorators.
