2. CONFIRMED ISSUES
====================

ISSUE 1: Frontend month selection is ignored
---------------------------------------------
Severity: HIGH
Area: Frontend contract/state
File: src/modules/attendance/Attendance.tsx

Root cause:
Attendance.tsx passes the selected month object directly to useAttendance, but the hook expects an options object containing month and year.

Current behavior:
The selected month changes visually, but the hook can fall back to the current month.

Expected behavior:
The selected month must be sent to /attendance/my-history.

Dependency: Independent.

ISSUE 2: /attendance/today response does not match the frontend contract
------------------------------------------------------------------------
Severity: CRITICAL
Area: Backend/frontend contract
Files:
- src/attendance/attendance.controller.ts
- src/attendance/attendance.service.ts
- frontend/src/services/api.ts

Root cause:
Backend /attendance/today calls getTodayStatusForEmployee, which returns the legacy getTodayStatus shape containing clockIn, clockOut, state, clockedIn, and clockedOut. The frontend primary contract expects punchInTime, punchOutTime, hasPunchedIn, and hasPunchedOut.

Current behavior:
Some frontend components tolerate clockIn; others do not.

Expected behavior:
One stable today-status response contract must be used everywhere.

Dependency: Causes Issues 3 and 4.

ISSUE 3: Employee Dashboard can show Punch In for an open record
-----------------------------------------------------------------
Severity: CRITICAL
Area: Frontend
File: frontend/src/modules/dashboard/EmployeeDashboard.tsx

Root cause:
The dashboard only checks hasPunchedIn and punchInTime. It ignores clockIn, clockedIn, and explicit state: IN_PROGRESS.

Current behavior:
Backend can correctly return IN_PROGRESS while the dashboard calculates no active punch and displays Punch In.

Expected behavior:
clockIn != null and clockOut == null must display Punch Out.

Dependency: Depends on Issue 2.

ISSUE 4: Attendance check-in time may not display
-------------------------------------------------
Severity: HIGH
Area: Frontend contract
File: frontend/src/modules/attendance/Attendance.tsx

Root cause:
Attendance.tsx directly reads todayRecord.punchInTime, while /attendance/today may return only clockIn.

Current behavior:
The action may detect an open record through a fallback, but the displayed check-in time can remain blank.

Expected behavior:
Display the backend check-in timestamp consistently.

Dependency: Depends on Issue 2.

ISSUE 5: Today-status failures are silently converted to not checked in
----------------------------------------------------------------------
Severity: HIGH
Area: Frontend error/state handling
File: frontend/src/hooks/useAttendance.ts

Root cause:
A /attendance/today failure clears todayRecord without setting the hook error.

Current behavior:
A failed or malformed today request can cause the UI to fall back to Check In.

Expected behavior:
Show an explicit refresh/error state and avoid presenting an unsafe punch action.

Dependency: Independent, but amplifies Issue 3.

ISSUE 6: Employee Attendance excludes FINANCE_MANAGER at route level
--------------------------------------------------------------------
Severity: HIGH
Area: Backend authorization
File: src/attendance/attendance.controller.ts

Root cause:
Employee Attendance role decorators omit FINANCE_MANAGER, although the authorization service allows Finance Manager employee access.

Current behavior:
Finance Manager UI visibility and backend authorization disagree; requests can return 403.

Expected behavior:
Finance Manager must retain the approved Employee Attendance visibility.

Dependency: Independent.

ISSUE 7: Employee 360 Finance Manager access is rejected in the service
------------------------------------------------------------------------
Severity: HIGH
Area: Backend authorization
File: src/attendance/attendance.service.ts

Root cause:
getTargetEmployeeAttendanceSummary explicitly rejects FINANCE_MANAGER.

Current behavior:
The controller allows Finance Manager, but the service rejects the request.

Expected behavior:
Approved Finance Manager scope must work consistently.

Dependency: Independent.

ISSUE 8: Working-day calculations use potentially different timezone semantics
-------------------------------------------------------------------------------
Severity: HIGH
Area: Backend date/time
Files:
- src/attendance/utils/business-date.util.ts
- src/common/working-days/working-days.service.ts
- src/attendance/attendance.service.ts

Root cause:
Attendance business dates use the Asia/Kolkata utility, but WorkingDaysService uses Date.getDay(), and getLocationStatus builds local server midnight boundaries manually.

Current behavior:
Weekday, holiday, leave, and location calculations can differ near midnight or when the server timezone is not Asia/Kolkata.

Expected behavior:
All Attendance date calculations must use one timezone model.

Dependency: Can affect history, leave, summaries, dashboard, and payroll.

ISSUE 9: Attendance consumers can trust stale persisted status
---------------------------------------------------------------
Severity: HIGH
Area: Cross-module
File: src/modules/reports/reports.service.ts

Root cause:
Some consumers derive status from record.status instead of first checking clockIn and clockOut.

Current behavior:
A stale open record stored as PRESENT can be counted as completed presence.

Expected behavior:
Open records must never count as completed PRESENT. Status must be derived from clock fields or the canonical classifier.

Dependency: Independent.

ISSUE 10: AttendanceRecord schema conflicts with application null-state logic
----------------------------------------------------------------------------
Severity: MEDIUM
Area: Database/application contract
Files:
- prisma/schema.prisma
- src/attendance/attendance.service.ts

Root cause:
Prisma declares AttendanceRecord.clockIn as non-null, while service logic handles clockIn == null and virtual absence rules.

Current behavior:
Virtual absences are synthesized in memory, but persisted records cannot represent the same state.

Expected behavior:
Persisted and virtual record contracts should be explicit and consistent.

Dependency: Affects null-state assumptions and test realism.

ISSUE 11: Employee Attendance has independent normalization and date filtering
------------------------------------------------------------------------------
Severity: MEDIUM
Area: Frontend
File: frontend/src/modules/attendance/EmployeeAttendance.tsx

Root cause:
EmployeeAttendance separately normalizes backend records and filters dates using browser-local Date.

Current behavior:
Details, summary, leave display, and month filtering can disagree near timezone/month boundaries.

Expected behavior:
Use the backend canonical month/date contract consistently.

Dependency: Related to Issue 8.

ISSUE 12: Employee Attendance does not expose pagination
-----------------------------------------------------------
Severity: MEDIUM
Area: Frontend/backend contract
Files:
- frontend/src/modules/attendance/EmployeeAttendance.tsx
- src/attendance/attendance.controller.ts

Root cause:
Employee monthly requests do not send page/pageSize and the UI has no pagination state.

Current behavior:
Employee Attendance loads the complete monthly array.

Expected behavior:
Either explicitly define bounded monthly data or implement pagination consistently.

Dependency: Independent.
