CANONICAL LIFECYCLE
-------------------
CHECK-IN:
  - Uses AttendanceRecord as the operational source.
  - Uses authenticated employee identity.
  - Stores server clockIn.
  - Stores clockOut = NULL.
  - Stores totalHours = NULL.
  - Stores status = IN_PROGRESS.
  - Creates the corresponding AttendanceLog IN event.
  - AttendanceRecord and AttendanceLog are written transactionally.

CHECK-OUT:
  - Requires the current business-date AttendanceRecord.
  - Requires an existing clockIn.
  - Rejects repeated checkout.
  - Rejects non-positive duration.
  - Uses server clockOut time.
  - Calculates totalHours from clockIn to clockOut.
  - Classifies completed attendance using one helper:
      duration < 4 hours       = ABSENT
      duration >= 4 and < 7    = HALF_DAY
      duration >= 7 hours      = PRESENT
  - Creates the corresponding AttendanceLog OUT event.
  - AttendanceRecord update and AttendanceLog creation are transactional.

LEGACY ROUTES
-------------
Legacy clock-in and clock-out routes remain available but now converge on the
canonical AttendanceRecord lifecycle where safely possible.

  - Legacy clock-in verifies the authenticated employee and active status.
  - Legacy clock-in creates canonical AttendanceRecord + IN log.
  - Legacy clock-out is restricted to the current business date.
  - Historical checkout is rejected.
  - Legacy fallback writes to the Attendance model were removed from punch
    operations.
  - The legacy Attendance model and its historical data were not deleted.

OPEN-RECORD INTERPRETATION
--------------------------
Attendance service reads project any record where:

  clockIn exists
  AND
  clockOut is NULL

as IN_PROGRESS, regardless of the stored PRESENT or LATE status.

This applies to Attendance history, summaries, administrative reads, self reads,
and today-status responses. Open records are not counted as final PRESENT inside
the Attendance module.
