HRMS DOCUMENTS VISIBILITY WORKFLOW FIX REPORT
==============================================

Date: 2026-09-08
Scope: Documents visibility and authorization workflow only

1. Executive Summary
--------------------
The remaining Documents visibility issue was fixed without changing the existing
upload mapping, document IDs, stored files, document types, schema, or approval
workflow.

Management roles now see pending, approved, and rejected document records.
Employees see only their own approved documents. Employee 360 also returns only
approved documents for the requested employee.

2. Root Cause
-------------
Document retrieval did not explicitly define separate management and employee
visibility queries.

The previous getDocuments implementation filtered only by employeeId when one
was provided and otherwise returned all records, but it did not enforce the
visibility policy inside the service. Employee 360 similarly returned all
statuses, including pending and rejected metadata.

This made the visibility behavior dependent on the calling path and did not
provide a clear, server-enforced distinction between:

- management access to all document statuses
- employee access to only their own approved documents
- Employee 360 access to approved document metadata only

The upload flow itself was not the cause. Existing upload records continue to
use employeeId + documentTypeId and preserve the documentTypeId-to-file mapping.

3. Business Rules Implemented
-----------------------------
Management roles:

- SUPER_ADMIN: organization-wide document access
- CEO: organization-wide document access
- HR: organization-wide document access

Management users can view pending, approved, and rejected records. Visibility
does not depend on uploadedBy, createdBy, or the current management user.

Employee:

- can read only the authenticated employee's own documents
- can see only APPROVED documents
- cannot see pending or rejected documents
- cannot access another employee's documents
- cannot upload, replace, edit, approve, reject, or delete documents

Denied roles:

- IT_MANAGER
- SALES_MANAGER
- FINANCE_MANAGER
- unknown or missing role

4. Visibility Queries
---------------------
Management query:

- management role is validated server-side
- optional employeeId scopes the existing selected-employee UI
- no status filter is applied
- no uploader filter is applied
- omitting employeeId returns records for all employees

Employee query:

- employee identity comes from authenticated request.user.employeeId
- client-supplied employeeId cannot select another employee
- query filters by authenticated employeeId
- query filters status = APPROVED

Employee 360 query:

- management roles may view the selected employee's approved metadata
- EMPLOYEE may view only their own approved metadata
- pending and rejected records are excluded
- binary fileData and sensitive internal fields are not returned

6. Upload/Data Integrity Preserved
----------------------------------
No upload behavior was changed.

The existing flow remains:

- repeated documentTypeIds are accepted
- files remain positionally mapped to documentTypeIds
- each record is keyed by employeeId + documentTypeId
- duplicate filenames are allowed
- duplicate filenames do not determine record identity
- status resets to PENDING when a document type is replaced
- Experience Letter, Payslip, and Relieving Letter mapping is preserved
- existing records, files, IDs, and document types are not deleted or reset
