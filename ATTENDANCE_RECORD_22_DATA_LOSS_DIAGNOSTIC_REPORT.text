ATTENDANCE RECORD 22 DATA-LOSS DIAGNOSTIC REPORT
================================================

Scope: Backend Attendance history response only
Code changes: NONE
Database changes: NONE

1. EXACT ROOT CAUSE
===================

The database record is correct, but AttendanceService.getAttendanceHistory() clears the real record's timestamps when its completed duration classifies as ABSENT.

Record id 22 has a duration below four hours, so ABSENT is the correct classification. However, the history merge treats every ABSENT status override as a virtual absence and replaces the real record fields with:

- clockIn: null
- clockOut: null
- totalHours: 0

This is response-layer data loss. The duration classification rule is not the problem.

2. EXACT FILE AND FUNCTION
==========================

File:
src/attendance/attendance.service.ts

Function:
AttendanceService.getAttendanceHistory()

Relevant merge block: the allRecords mapping after real records and inferred virtual records are combined.

3. EXACT CODE PATH
==================

GET /attendance/my-history
-> AttendanceController.getMyAttendance()
-> AttendanceService.getMyAttendanceForEmployee()
-> AttendanceService.getAttendanceHistory()
-> attendanceRecord.findMany()
-> effectiveRecord()
-> buildLeaveAwareStatusMap()
-> allRecords mapping
-> pagination
-> response

The real database record is fetched and classified correctly:

const records = (...).map((record) => this.effectiveRecord(record));

For record id 22:

- clockIn exists
- clockOut exists
- totalHours is less than 4
- effective status becomes ABSENT

The merge then executes the ABSENT override branch:

const isLeaveOrAbsent =
  overrideStatus === AttendanceStatus.LEAVE ||
  overrideStatus === AttendanceStatus.ABSENT;

return isLeaveOrAbsent
  ? {
      ...record,
      status: overrideStatus,
      clockIn: null,
      clockOut: null,
      totalHours: 0,
    }
  : { ...record, status: overrideStatus };

That branch is intended for virtual ABSENT/LEAVE rows, but it also runs for real records. Therefore the response contains ABSENT with null timestamps even though the database row has real timestamps.

Pagination and frontend response normalization do not remove the timestamps. The timestamps are already null before pagination and serialization.

5. SMALLEST SAFE FIX
====================

Only clear timestamps when the merged item is a virtual record with no real clockIn.

Conceptually:

if (record.clockIn) {
  return { ...record, status: overrideStatus };
}

return {
  ...record,
  status: overrideStatus,
  clockIn: null,
  clockOut: null,
  totalHours: 0,
};

This preserves:

- ABSENT classification for completed durations below four hours
- real clockIn
- real clockOut
- real totalHours
- real AttendanceRecord metadata
- virtual ABSENT and LEAVE behavior
- pagination and ordering

No frontend, schema, migration, or database changes are required.
